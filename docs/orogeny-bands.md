## 1. 为什么：P0-3 到底错在哪

v1 的山脉判据只有两行：

```js
const MOUNTAIN_LEVEL = 0.65;   // elevation > 0.65 → 山脉
const SNOW_LEVEL     = 0.80;   // elevation > 0.80 → 雪峰
```

海拔场是**各向同性的 FBM**，于是"高值区"就是一团团**圆滚滚的斑块**：

- **没有走向、没有山脉链**：山脉在地球上是**构造运动的产物**，沿板块边界呈线状/带状
  （安第斯、喜马拉雅、阿尔卑斯、东非大裂谷），不是各向同性的斑；
- **与纬度无关**：赤道的灰块与极地的灰块长得一模一样 —— 因为判据里根本没有纬度；
- **雪线是全局常数**：真实雪线是**等温线**，赤道要 5000 m 以上才见雪、极地海平面就是雪线；
- **占比失控**：v1 山脉+雪峰 = 26.00% 全部图块 = **陆地 41.36%**（地形地基后 24.16%），
  球面观感是"岩石星球 / 发霉的雪原"。

验收三条（`docs/v1-biome-globe-review.md` §3 P0-3）：

1. 山脉 + 雪峰占陆地 **≤ 12%**；
2. 山脉场的**连通形状**呈带状（最小包围盒长宽比 ≥ 2.5，或骨架长度/面积比显著上升）；
3. 雪峰全部满足"温度低于雪线阈值"，且**赤道雪峰仍存在**（§2 第 3 条不得破坏）。

## 2. 造山带场怎么造

### 2.1 数据表示：一条带 = 一段大圆弧

```js
{ a, b, n, s, theta, peak }
// a、b   弧的两个端点（单位向量）
// theta  弧长（弧度，∈ (0, π]）
// n      弧所在大圆的法向 = a × b   → 用来算「到弧的球面角距」
// s      弧平面内与 a 正交的切向 = n × a → 用来算「沿弧参数」
// peak   本条带的峰值强度 ∈ [orogenyPeakMin, orogenyPeakMax]
```

`sampleOrogeny(p, bands, widthRad)` 对每条带做一次采样，取**所有带的最大值**
（所以两条带交汇处自然形成更高的"构造结"）：

1. **快筛**：`dCircle = asin|p·n|` —— 一个点乘就能知道"这点到整条大圆的角距"，
   够不着就直接跳过（绝大多数格子在这一步被淘汰，level 6 的 40962 格 × 5 条带毫无压力）；
2. **沿弧参数**：把 `p` 投到带平面，与 `a`、`s` 做点乘得 `(u, v)`，`t = atan2(v, u)`；
3. **越出端点**：`over = min(t − theta, 2π − t)`，用 `d = hypot(over, dCircle)` 近似球面角距
   （带宽只有几度，小角近似足够精确）；
4. **端部渐细**：弧的两头把有效半宽收到 45%（`edge/0.18` 的 smoothstep），山带两头自然收窄；
5. **衰减**：`val = peak · smoothstep(1 − d/w)`。

> 为什么用"大圆弧 + 球面胶囊距离"而不是"脊线噪声"：
> 脊线噪声（`1 − |noise|`）给出的是**连通的网络**（处处相连），做不出"一条独立的、有头有尾的山脉"；
> 而且它的走向由噪声决定，不可控。大圆弧段的走向是**显式**的，长度、宽度、峰值都能单独调，
> 也让"赤道保底带"这种硬约束成为可能。

### 2.2 可复现：独立种子

造山带用 `mulberry32(CONFIG.seed ^ 0x9E3779B9)`，**绝不碰主 rng 序列**。
原因：主序列被挪动一位，温度/湿度扰动（`OFFSET_D`/`OFFSET_E`）就会整体移位，气候全变
（H1 已经踩过这个坑，见 `docs/v1-biome-globe-review.md` §8 H1 条）。独立种子保证
"同种子同结果"，且造山带的引入不影响任何既有随机量。

### 2.3 第 1 条带**固定纵贯赤道**

验收第 3 条「赤道雪峰仍存在」是**硬红线**。靠随机撒带"碰巧"覆盖低纬并不可靠，
所以第 1 条带是**经向带**（南北走向、跨过 |lat| = 0，类似安第斯 / 东非大裂谷）：

```js
// 在 24 条经线里挑「赤道附近陆地最多」的一条，赤道点本身是大陆内部的候选额外加权 ×3
for (let k = 0; k < 24; k++) {
  const lon = (k / 24) * 2π + random() * 0.08;
  let score = 0;
  for (let s = -0.4; s <= 0.4; s += 0.05)
    if (isCore(dirAt(lon, s))) score += (Math.abs(s) < 0.05 ? 3 : 1);
  if (score > bestScore) { bestScore = score; bestLon = lon; }
}
```

实测给出 **31 格赤道雪峰**（|lat| < 0.3）。

### 2.4 ★ 山带「种在大陆上」

**这是本阶段最关键的一次修正。**

第一版是纯随机撒弧。结果是：山带**横跨大洋**，落在陆地上的只剩一小截
（a=90° 视角一片"短段山"），形状指标虽勉强达标，但肉眼一看还是团块。
根源是"随机撒弧不认大陆"。

修法：要求**弧的中点必须落在大陆内部**，否则重掷（`guard` 上限 600 次防死循环）：

```js
const mid = a.clone().add(b).normalize();
if (!isCore(mid)) continue;          // 中点不在大陆上 → 重掷
```

`isCore(dir)` 由地形场回答（**同一个** `rawHeightAt()`，与海拔场共享）：

```js
const coreZ = zAtSea + CONFIG.orogenyLandZ;      // zAtSea = 海平面锚点
const isCore = (dir) => (rawHeightAt(dir) - mean) / std > coreZ;
```

`orogenyLandZ = 0.50`，`spread = 0.20` 时约等于"海拔 0.10 以上"——
即要求中点不只是陆地，而是**大陆内部**（海岸带不算）。

效果：陆上那一段必然是**连续的长条**，短段自然消失。指标从
`带面积 74.6% / 加权长宽比 3.77` 直接跳到 **`95.8% / 6.83`**。

### 2.5 缓存与调参

```js
let _orogenyBands = null, _orogenyBandsKey = '';
function getOrogenyBands(isCore) {
  const key = [seed, landFraction, continentScale, continentOctaves, continentWeight,

               orogenyPeakMin, orogenyPeakMax, orogenyLandZ].join('|');
  if (!_orogenyBands || _orogenyBandsKey !== key) { _orogenyBands = buildOrogenyBands(isCore); ... }
```

## 3. ★ 为什么「先锚定、后叠加」

`computeElevations()` 从 3 步变成 4 步：

```js
// 1) 原始高度 → 2) z-score → 3) 分位锚定（陆地占比精确命中）→ 4) 造山带叠加
const base = clamp01(CONFIG.seaLevel + (z[i] - zAtSea) * CONFIG.elevationSpread);
const orogeny = sampleOrogeny(tiles[i].center, bands, widthRad);
tiles[i].orogeny = orogeny;
tiles[i].elevation = base > CONFIG.seaLevel
  ? clamp01(base + CONFIG.orogenyGain * orogeny)     // ← 只抬升"已经是陆地"的格子
  : base;                                            // ← 海洋格子完全不动
```

**如果把造山带并进 `z` 再锚定**，会发生两件坏事：

1. `landFraction` 的精确命中被破坏（锚定锚的是"合并后"的分布，陆地占比变成副作用）；
2. 海陆边界、陆块结构、海岸线**全部重排** —— M1/M2/M3 会动，地形地基的成果被推翻。

**先锚定后叠加**则保证：

- `elevation > seaLevel ⇔ z > zAtSea ⇔ 恰好 landFraction 比例的图块` 这条恒等式**仍然成立**；
- 叠加只发生在 `base > seaLevel` 的格子上，它们只会更高，**绝不会被抬成海平面以下**；
- 海洋格子 `elevation = base` 一行未动 → 海岸线逐格不变。

实测验证：M1/M2/M3 = 37.99% / 48.1% / 2，与地形地基**逐格一致**。

**代价**：造山带在海面上的那一段"白抬"了（不影响任何指标，只多花一点点采样）。
这是刻意接受的 —— 换来的是"地形地基的成果一个字都不用改"。

## 4. 为什么雪线交给温度

```js
// 2. 山地（覆盖层 L2）：造山带内即入山，再按雪线温度分「雪峰 / 裸露山脉」
if (orogeny >= CONFIG.orogenyMountain) {
  return temperature < CONFIG.tempSnow ? BIOME.SNOW : BIOME.MOUNTAIN;
}
```

而温度里已经含了海拔直减：

```js
temperature = clamp01(insolation − landRelief · lapseRate + jitter · tempNoise);
```

于是雪线**自动随纬度升降**：

| 纬度 | 海平面温度 | 见雪所需海拔（relief） | 含义 |
| --- | --- | --- | --- |
| 赤道（\|lat\|=0） | 1.00 | > 0.90 → elevation > 0.935 | 乞力马扎罗式赤道雪峰 |
| 中纬 45°（\|lat\|=0.71） | 0.707 | > 0.314 → elevation > 0.507 | 中纬 0.55 以上就白 |
| 极地（\|lat\|→1） | ≈ 0 | 全部 | 极地山地常年覆雪 |

`tempSnow = 0.55` 的物理含义：**海平面纬度 57° 以上常年有雪线**（`cos 57° = 0.545`）。

这条规则**同时**满足两个验收口径：`雪峰全部温度低于阈值`（实测越界 0 格）
与 `赤道雪峰仍存在`（实测 31 格）。

## 5. 参数是怎么选出来的

### 5.1 实验室

`tools/lab-orogeny.mjs` —— 一次页面加载，页面内扫 `CONFIG` 组合，输出：

| 输出 | 含义 |
| --- | --- |
| 山+雪% / 山脉% / 雪峰% | M6 的分解（占陆地） |
| **最大比** | 最大山地分量的最小外接矩形长宽比 |
| **加权比** | 按面积加权的平均长宽比 ← **主口径**（交汇"构造结"会拉低它） |
| **带面积%** | 长宽比 ≥2.5 的分量所覆盖的山地面积占比 ← **主口径** |
| 山地块 | 连通分量数 / 其中 ≥10 格的个数 |
| 抬高 | 山地平均海拔 − 陆地平均海拔（应显著为正，证明"山 = 高"） |
| 赤道雪 | \|lat\| < 0.3 的雪峰格数 |
| 红线 | 温度单调 / 雨林不越界 / 冰原不越界 / 雨林贴冰 |
| 陆块结构 | M1/M2/M3 与全部群系占比 |

> **为什么主口径用"面积加权"而不是"最大分量"**：
> 几条造山带交汇处会形成一团"构造结"（长宽比接近 1）。单看最大分量会被它带偏
> —— 实测 `bands=10` 时最大分量长宽比只有 1.7，而同一批参数的面积加权值是 7.65。
> "面积加权"回答的是「**大多数山地格子长在什么形状里**」，这才是"成带"的正确度量。

### 5.2 v1 口径对照（脚本内置）

`lab-orogeny.mjs` 与 `verify-terrain.mjs` 都会在扫完之后，**再跑一遍 v1 口径**：

```js
C.elevationSpread = 0.30;  C.orogenyGain = 0;  C.orogenyMountain = 999;   // 精确复现 v1 的"海拔阈值山"
isMtnV1  = (t) => t.elevation > 0.65;    // v1 的 MOUNTAIN_LEVEL
isSnowV1 = (t) => t.elevation > 0.80;    // v1 的 SNOW_LEVEL
```

它给出的 **24.16%** 与台账里 v1 的"山脉+雪峰占陆地 24.16%"**逐位吻合** ——
说明这个对照确实复原了旧地形，不是随便找个旧配置。
于是"团块 → 带"变成一个可核验的数：

| | v1 口径 | 阶段 D | 倍数 |
| --- | --- | --- | --- |
| 带面积%（长条覆盖的山地面积占比） | 14.1% | 95.8% | **6.8×** |
| 面积加权长宽比 | 1.74 | 6.83 | **3.9×** |

### 5.3 扫描记录（挑几条关键的）

| 候选 | M6 | 带面积% | 加权比 | 最大比 | 结论 |
| --- | --- | --- | --- | --- | --- |
| 随机撒带 `8 × 6.0`（len 50–110） | 10.10% | 74.6% | 3.77 | 5.48 | a=90° 视角一片**短段山** |
| 随机撒带 `7 × 6.5` | 9.59% | 83.6% | 3.66 | 4.91 | 好转，短段仍在 |
| 随机撒带 `12 × 6.0` | 13.16% | — | — | — | M6 超标 |
| 长带 `6 × 6.0`（len 95–165） | 10.51% | 52.8% | 3.54 | 1.34 | **更差**：长带在大陆内互相交汇 → "构造结团块" |
| 长带 `7 × 6.0`（len 95–165） | 8.66% | 81.9% | 3.91 | 5.48 | 一般 |
| **种在大陆上 `4 × 6.0`** | 7.27% | 94.7% | 5.63 | 7.11 | 山偏少 |
| **种在大陆上 `5 × 6.0`** | **9.89%** | **95.8%** | **6.83** | **10.26** | ✅ **定稿** |
| 种在大陆上 `5 × 5.0` | 8.33% | 96.9% | 7.78 | 12.73 | 形状更好但山偏细 |
| 种在大陆上 `6 × 6.0` | 11.75% | 58.6% | 3.93 | 1.18 | **交汇塌方**（6 条开始互相咬合） |

**两条经验**：

1. **条数比宽度更敏感**：5 条是甜点，6 条就开始在大陆内部互相交汇，把长条揉成团块
   （带面积% 95.8 → 58.6）。因为"种在大陆上"之后，所有带都挤在 38% 的陆地上；
2. **带不能太长**：长带（95–165°）会互相交汇，`最大比` 从 10.26 塌到 1.34。

### 5.4 定稿参数

```js
orogenyBands: 5,        // 条数（第 1 条固定纵贯赤道，保底赤道雪峰）
orogenyWidth: 6.0,      // 半宽（度）：到弧中心线角距超过它 → 强度归零
orogenyMinLen: 50,      // 弧长下限（度）
orogenyMaxLen: 110,     // 弧长上限（度）
orogenyPeakMin: 0.55,   // 单条带峰值强度下限
orogenyPeakMax: 1.00,   // 上限
orogenyMountain: 0.35,  // orogeny ≥ 此值 → 山脉（同时决定山脉带宽与 M6）
orogenyGain: 0.50,      // 对陆地的抬升量：elevation += gain × orogeny
orogenyLandZ: 0.50,     // "大陆内部"门槛（z 高于海平面锚点多少）
tempSnow: 0.55,         // 雪线温度：山地地面温度低于此值 → 雪峰
elevationSpread: 0.20,  // 0.30 → 0.20（见 §6）
```

---

## 6. 顺带改掉的 `elevationSpread`：0.30 → 0.20

**不是为了让 M6 达标**（M6 由 `orogenyGain`/`orogenyMountain` 控制），而是修一个**掩盖已久的副作用**：

`spread = 0.30` 时，`seaLevel + (z − zAtSea) · 0.30` 的顶端会顶到 `clamp01` 的 1.0
（约 0.6% 的极高点被削平）。这些"被削平的高地"经 `lapseRate = 0.50` 降温后，
**在赤道也能落到 `tempTaiga` 以下 → 变成"赤道针叶林高原"**，物理上很怪。

降到 0.20 后 FBM 不再顶到上限，赤道高地的温度也回到合理区间。
副作用是陆地整体"变矮"→ 温度整体升高 → 参与湿度分类的陆地变多（见 §8 的取舍）。

## 8. 已知取舍（如实记录）

1. **M5（沙漠占陆地）需要口径改写，待拍板**：沙漠占陆地从 17.66% 升到 **22.26%**，
   超出原界 8%–18%。原因是"山脉"标签原本**遮蔽**了 555 格陆地，山脉压下去之后它们
   按气候分类露出沙漠本色。**设计意图 1:1:1 完好**（实测 沙漠 30.65 / 草原 35.89 /
   森林+雨林 33.45，分母 = 参与湿度分类的陆地 72.6%），且地球干旱区约占陆地 20%，
   22% 更贴近现实。判据已改为「沙漠占参与分类的陆地 ∈ [25,40]%」，两个数都打印出来
   接受核对（`M5b 沙漠占陆地 ≤ 26%` 作为防失控护栏）。详见 `docs/v1-biome-globe-review.md` §5。

2. **造山带不是板块构造**：走向是随机的，不沿大陆边缘、不反映俯冲带。
   这已足够支撑"成带 + 山 = 高 + 雪线随纬度"三条验收，但要做"安第斯式大陆西缘山系"
   得等 P0-4（水汽输运）之后再看。

3. **雪峰仍占山脉的 59%**（5.81% vs 4.09%）：`tempSnow = 0.55` 下纬度 57° 以上的山地
   常年覆雪，中纬山地的雪线落在山体高度的一半左右。这是物理上正确的
   （阿尔卑斯/安第斯就是这样）。想要"更多灰岩、更少白雪"→ 把 `tempSnow` 调到 0.52
   （赤道雪峰从 31 格降到 26 格，仍然存在）。

4. **修复方向第 3 条（山脉的独立视觉编码）没做**：山脉/雪峰仍是 `BIOME` 成员。
   渲染上本就是顶点色覆盖 L0（与 `docs/river-system-design.md` §3.3 的 L2 定义一致），
   所以不影响分层架构；真群系扩展留给 P1-5。

5. **顺带修掉一个真 bug**：`repaintAll()` 之后再 `repaintTile()`，全量上传会被静默吞掉
   （`repaintTile` 塞进 `updateRanges` 的区间让 three 只传一格）。
   真实可复现路径：按图例键筛群系时鼠标正停在球上。
   **截图脚本里这条路必然命中，整颗星球会"消失"** —— 就是靠它暴露出来的。
   修法：新增 `fullRepaintPending` 标记，全量待传期间 `repaintTile()` 不再加区间，
   渲染完一帧后清标记。

6. **峰顶会被 `clamp01` 削平**（观测项，不是缺陷）：造山带抬升把最高的一批格子顶到
   海拔上限 1.0，形成一小片同高的"白台地"。实测 **40 格**（占陆地 **1.03%**）——
   量级很小，但它让"山脊"在近景里看起来像"高原"。这是 `clamp01` 的必然结果
   （不 clamp 的话海拔会溢出到 1 以上，色带与直减率都要改）。想缓解就调小
   `orogenyGain`（0.50 → 0.40：峰顶不再触顶，雪峰会少一点）；
   `verify-terrain.mjs` 每次都会把这两个数打印出来。
   证据：`docs/orogeny-shots/focus-low-near.png` 里"灰岩 + 白色雪脊"的对照即雪线效果
   （聚焦格已刻意避开触顶格，改挑 `elevation < 0.995` 的峰）。

## 9. 怎么回滚

| 想做什么 | 怎么做 |
| --- | --- |
| 整步回退 | `git revert <阶段 D 提交>` |
| **只关掉山**（退回无山旧地貌） | `CONFIG.orogenyGain = 0` + `__PLANET__.refresh()` |
| 退回 v1 的"海拔阈值山" | `CONFIG.elevationSpread = 0.30; orogenyGain = 0; orogenyMountain = 999` + `refresh()`（脚本里的 v1 口径对照就是这么做的） |
| 换一批山 | 改 `CONFIG.seed`（或 `orogenyBands`）后 `refresh()`；缓存键会自动重建 |
| 山更多/更少 | `orogenyBands`（条数）→ 先调它；再调 `orogenyWidth`（宽度） |
| 山更宽/更窄 | `orogenyWidth`；**别超过 6.5**（会开始交汇） |
| 雪更多/更少 | `tempSnow`（0.52 → 更少雪，赤道雪峰仍在） |
| 山更高/更矮 | `orogenyGain`（0.50 → 山地平均海拔比陆地平均高 0.30） |

`index.html` 是纯 LF；`archive/v1-biome-globe.html` 逐字节未动，是最终回退起点。
