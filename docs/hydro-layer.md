## 1. 目标与改动清单

**目标**（对应 P0-2「河流是噪声等值线网络，没有重力、没有汇水、没有湖泊」）：
把河流从"另一路噪声的零值线"换成**重力驱动**的河网 —— 填平洼地 → 多流向分配 → 汇水累积 →
阈值提取，让河网**从地形上长出来**，天然有流向、天然成树枝。

**为什么必须先有"数据层"这一步**：设计书的施工顺序是 H1（架构）→ H2（数据）→ H3（渲染）→
H4（湖泊）→ H5（标定）。H2 单独成步的理由是**可验证性**：如果数据和渲染一起上，
画面不对时无法区分"算错了"还是"画错了"。H2 的产出是纯数据，可以用定理逐条判真伪。

## 2. `world.hydro` 契约（16 个字段）

纯数据、一次性算完、运行时不重算，**渲染层不感知**。字段与设计书 §6.1 一致：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `adj` | `number[][]` | 邻接表（**公共设施**：水文与将来所有相邻关系计算的公共输入） |
| `filled` | `Float64Array` | 填平后的水面高程（≥ `elevation`） |
| `depth` | `Float64Array` | `filled − elevation`（= 湖深；正数即被淹格） |
| `runoff` | `Float64Array` | 每格产流 = `moisture^runoffExponent × 冷度` |
| `accum` | `Float64Array` | 汇水量（按降水量加权；`÷ unit` = "等效格数"） |
| `unit` | `number` | 陆地平均产流（"等效格数"的除数，河网阈值也用它） |
| `w` | `{start,target,prob}` | 多流向分配的 CSR 布局（Σ prob = 1） |
| `down` | `Int32Array` | 主下游（argmax 权重）；`-1` = 入海 / 终点 |
| `isRiver` | `Uint8Array` | 1 = 该格有河道穿过（★ 放在 `hydro` 里，**不是** tile 上） |
| `isSource` | `Uint8Array` | 1 = 河源（有河、无上游河格） |
| `isMouth` | `Uint8Array` | 1 = 河口（有河、主下游是海洋） |
| `lakeId` | `Int32Array` | `-1` = 非湖；否则湖泊编号（★ H4：只标**要按湖色画的格子**） |
| `lakes` | `[]` | 湖泊属性表，见下（★ H4 从 9 个字段扩到 14 个） |
| `riverCount` | `number` | 河格总数（剪枝后） |
| `pruned` | `{deadEnds,isolated}` | 剪枝删掉的格子数（断头河 / 孤立河点） |
| `sinkRounds` | `number` | ★ H4.5：内流盆地当"汇"的截断**迭代轮数**（实测 1，上限 5） |
| `sinkBlocked` | `number` | ★ H4.5：被清零的**出边条数**（> 0 才说明水真的被内流盆地拦住了） |
| `ms` | `number` | 数据层耗时（ms） |

**`lakes[i]` 的字段（★ H4 定稿）**：

| 字段 | 含义 |
| --- | --- |
| `id` | 编号（= 数组下标） |
| `basinArea` | **洼地**面积（`depth > minLakeDepth` 的连通分量格数，地形尺度，与气候无关） |
| `wetArea` | **湿面积**（水位以下的格数）—— 内流盆地的干底 `wetArea = 0` |
| `depthMean` / `depthMax` | 按**水位**算的深浅（不是按填平面） |
| `spillLevel` | 溢出点高程：水位顶到这里就开始出水 |
| `outlet` | 溢出点所在的格子（出湖河从这里出发） |
| `level` | 水位：外流湖 = `spillLevel`；内流湖 = 水量平衡解出来的平衡水位 |
| `inflow` | 入流 = 湖面自身产流 + 从湖外流进来的**全部**汇水（按 MFD 分流比例累加） |
| `evap` | 水位处的湖面总蒸发 |
| `outflow` | 外流湖 = `inflow − evap`；内流湖 = `0` |
| `isEndorheic` | `true` = 内流（蒸发追平汇水，水面到不了溢出点）→ 盐湖 |
| `tier` | 渲染分档：`'shallow'` / `'deep'` / `'salt'`（见 §7.4） |

> `lakeId` 的语义是"**要按湖色画的格子**"，不是"被水淹的格子"：外流湖只有水位以下的湿格；
> **内流盆地画整个封闭洼地**（盐随水来、随蒸发留在盆底，会铺满盆地 —— 卫星图上的塔里木、
> 大自流盆地、乌尤尼都是这样）。这样"判成内流盆地却什么都看不见"不会发生。

**参数（`CONFIG.hydro`）**：H2 落地 6 个**数据层**参数，H3 加 8 个**渲染层**参数，H4 加 2 个（1 个数据层 + 1 个渲染层）。

| 参数 | 值 | 层 | 含义 | 谁在管 |
| --- | --- | --- | --- | --- |
| `runoffExponent` | 1.5 | H2 | 降水 → 产流的非线性：>1 拉开干湿差（湿处河密、干处河疏） | 河网密度差 |
| `fillEpsilon` | 1e-4 | H2 | Priority-Flood 每步的抬升量：保证 `filled` 处处严格下坡 | 湖泊数 / 河道走位 |
| `flowExponent` | 1.1 | H2 | 多流向的坡度幂：1 = 最平滑，越大越接近"只走最陡邻居" | 格网指纹 |
| `riverCellThreshold` | **12** | H2 | 河网阈值，单位「等效格数」（`accum ÷ unit`） | 见 §3 |
| `minLakeDepth` | 0.002 | H2 | 低于此深度不算被淹（ε 填平留下的"过水段"不是湖） | M17 |
| `minLakeArea` | **3** | H2→H4 | 小于此格数的洼地不画成湖（H4 从 4 调到 3，见 §7.2） | M17 |
| `riverWidthScale` 等 8 个 | — | H3 | 河宽 / 抬升 / 抖动 / 平滑 / 气候耦合 | 见 §6.3 |
| `potentialEvaporation` | **2.0** | **H4** | 潜在蒸发强度（单位与产流一致：1 ≈ 陆地平均产流）—— **内流盆地数量的唯一旋钮** | M18 |
| `lakeShallowDepth` | **0.006** | **H4** | 浅湖 / 深湖的分档阈值（按 `depthMean`） | 湖面颜色 |

> **刻意不提前加的**：`riverWidth*` / `riverLift` / `nodeJitter` / `climateCoupling` 在 **H3** 加，
> `potentialEvaporation` 在 **H4** 加。**用不到的配置项就是负债。**

## 3. 标定：阈值 12 是怎么选出来的

### 3.1 扫描结果（`tools/lab-hydro.mjs`，54 组）

`T ∈ {3,5,8,12,20,30} × F ∈ {1.0,1.1,1.3} × R ∈ {1.0,1.5,2.0}`。
下表取 `F=1.1, R=1.5`（H2 的默认配置）这一列：

| T | 河格 | 占陆地 | 中位汇水（等效格） | 海拔差 | 格环数¹ | 格连通分量¹ | 格最大分量¹ | 河格平均度² | 度≥3² |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 3 | 6396 | 41.1% | 5.9 | −0.0190 | 8940 | 79 | 715 | 4.77 | 93.7% |
| 5 | 3900 | 25.1% | 8.4 | −0.0335 | 4762 | 102 | 477 | 4.39 | 89.2% |
| 8 | 2054 | 13.2% | 12.8 | −0.0458 | 2085 | 108 | 120 | 3.93 | 81.5% |
| **12** | **1066** | **6.85%** | **20.7** | **−0.0592** | 941 | 75 | 89 | 3.62 | 76.5% |
| 20 | 526 | 3.4% | 32.4 | −0.0714 | 359 | 47 | 54 | 3.19 | 66.3% |
| 30 | 279 | 1.8% | 55.3 | −0.0707 | 140 | 30 | 39 | 2.79 | 56.6% |

¹ 这是 **v1 台账口径**（在"河格的二维邻接图"上量环数 / 连通分量 / 最大分量），见 §3.2 —— 已废弃。
² "线 vs 片"诊断：**一棵一维的树，平均度应 ≈ 2**。见 §6。

**为什么是 12**：12 是**满足"河格汇水面积中位数 ≥ 20 等效格"的最小阈值**
（中位数 ≈ 1.6–1.8 × T；T=12 → 20.7 格，T=8 只有 12.8 格）。
这条指标的意思是"一条被标成河的格子，上游至少攒够 20 格的水" —— 低于它就只是小溪沟。

### 3.2 ★ 三个目标在阈值上**互相冲突**（这是改写 M12/M13/M14 的硬证据）

把 54 组按"每个目标能不能达标"分组，得到一张**无交集**表：

| v1 台账目标 | 达标所需的 T | 证据（54 组里的极值） | 但同一 T 下另一个目标失守 |
| --- | --- | --- | --- |
| M12 河网环数 ≤ 3 | **不存在** | 全表最小值 **93**（T=30 F=1.3 R=1） | — |
| M13 连通分量 ≤ 30 | 只有 **T ≥ 30** | T=30 → 26…33 | 那里 M14 只有 **34…40** 格（要 ≥ 200） |
| M14 最大连通水系 ≥ 200 格 | 只有 **T ≤ 5** | T=5 → 384…503；T=3 → 706…837 | 那里 M16 只有 **−0.0307…−0.0381**（要 ≤ −0.04） |
| M16 河流比低地低 ≥ 0.04 | 只有 **T ≥ 8** | T=8 → −0.0433…−0.0527 | 那里 M14 只有 **104…170** 格（要 ≥ 200） |

**结论：M14 ∩ M16 = ∅，M13 ∩ M14 = ∅，M12 = ∅。** 也就是说，v1 的这套口径
**在重力河网上根本不可能同时达标** —— 不是"没调好"，是定义本身不适用。

**为什么会这样（两条独立的原因）**：

1. **口径不适用**：v1 的"河"是**整格填蓝的色块**，所以"147 个连通分量"确实说明它碎。
   换成重力河网后，河格是一片**连续的二维区域**，它的邻接图**天然含环**
   （两条平行河道只要隔一格相邻就成环）→ 环数必然成百上千。这不是缺陷，是二维区域的定义使然。
2. **物理量互相冲突**：想让主干长（M14 ≥ 200 格）就得把阈值压低到 T ≤ 5，
   而阈值一低，河格就漫到缓坡上，河流与低地的平均海拔差必然缩小（M16 失守）。这是**真冲突**。

### 3.3 口径改写（★ 待用户拍板）

`tools/verify-hydro.mjs` 改成量**与阈值无关、且真正表达意图**的量：

| 指标 | 新口径 | 目标 | 为什么它表达原意 |
| --- | --- | --- | --- |
| M12 | **流图环数 = 0** | = 0 | 原意是"河道不该互相交叉成网"。"水怎么走"的**流图**是森林（每格只有一个主下游），环数恒为 0 —— 这才是原意 |
| M13 | **河网可达性 = 100%** | = 100% | 原意是"河流不该碎成孤立的点"。改成"每个河格顺主下游都能走到河口" |
| M14 | **最大汇水面积（陆地格）≥ 200 等效格** | ≥ 200 | 原意是"得有一条像样的主干河"。改成量**汇水面积**，与阈值无关 |

**v1 口径的三个数照旧打印**（标为「对照」），只是不再判成败：
`环 941 · 连通分量 75 · 最大分量 89 格`（对照 v1 基线 `126 / 147 / 44`）。

> ⚠ **M14 取数有个坑**：**不能按全图取 `max(accum)`**。全图最大的一格是
> "入海口那一格海水" —— 整个流域的水都汇到它身上（实测 **650.2** 等效格），

## 4. 施工记录

### 4.1 ★ 设计稿有一条定理写错了（实测发现）

设计书 §8.4 原文：

> 「孤立河点 = 0 —— 下游的 `accum` 必 ≥ 本格（§4.5 定理 2），所以有河格的下游也是有河格
> （除非入海）」，并据此断言"**不需要任何后处理**"。

**那个推导只在单流向（水 100% 给一个邻居）下成立。** 我们用多流向（MFD，按坡度幂分给多个邻居），
主下游只拿到**一部分**水，于是 `accum[主下游] < accum[本格]` 完全可能 → `accum` 不再单调。
**实测未剪枝时孤立河点占 1.2–2.4%、断头河一片。**

所以 `extractRivers()` 加了**两步剪枝**：

| 步 | 做法 | 保证 |
| --- | --- | --- |
| ① 断头河 | 沿 `filled` **升序**（下游优先）标记，只保留"主下游一路合法到河口"的河格 | 不存在"流到一半断掉"的河 |
| ② 孤立河点 | 删掉没有任何相邻河格的河格 | 不存在单格孤点 |

剪枝量很小（level 6：断头河 **23** 格、孤立 **20** 格，占 1066 的 4%），
但剪完之后 §8.4 那两条才**真正**是定理。设计书 §8.4 已按实测修正。

### 5.3 算法定理（**构造保证**，不是调参调出来的）

| 定理 | 实测 |
| --- | --- |
| Σdeg = 2E | 245760 / 245760 |
| `filled ≥ elevation` | Priority-Flood 的 `max()` 保证 |
| 下游严格递减（不可能成环） | 每步 `+fillEpsilon` |
| 陆地格必有主下游（无陆地洼地） | ε 填平后处处有下坡（★ H4.5 起**排掉内流盆地格**：实测 75 格 `down = −1` 属正常，那是"水到湖为止"，见 §7.6③） |
| 每个陆地格都能走到海洋 | 走不到 **0** 格（★ H4.5 起改成"走到**汇** = 海 或 内流盆地"，否则内流盆地的上游会被记成走不到） |

## 6. ★★ 已知风险：河网偏"二维"，H3 的第一号风险

### 6.1 证据

**指标**：一棵**一维的树**，河格平均度应 ≈ 2、度 ≥ 3 应接近 0。实测：

| T | 河格平均度 | 度 ≥ 3 占比 | 度分布 [0..6] |

| 20 | 3.19 | 66.3% | 0/56/121/135/137/37/40 |
| 30 | 2.79 | 56.6% | 0/41/80/82/55/15/6 |

**形状**（`tools/lab-hydro-map.mjs` 正交投影成 2D 图，不需要任何三维渲染）：

| 阈值 | 证据图 | 观感 |
| --- | --- | --- |
| 12 | `docs/hydro-shots/river-network-t12-f1.1.png` | **以树枝状为主**，但在**汇流处会局部糊成二维片**（左侧和右侧各有一团密集平行线） |

## 7. ★ H4：湖泊 / 内流盆地（湖面水量平衡）

### 7.1 为什么"填平"得不到内流盆地

Priority-Flood 会把**每一个**洼地都填到"水能流出去"为止 —— 所以在拓扑上，
**H2 得到的每个湖都是外流湖**（这就是设计书 §4.7 说的坑）。

真实的里海 / 咸海 / 大盐湖 / 塔里木**不是拓扑封闭**，而是**蒸发 ≥ 补给**：

> 湖面会一直上升，直到"溢出"或"蒸发量追平汇水量"。
> · 在到达溢出点**之前**蒸发就追平了汇水 → 水面停在溢出点以下 → **内流湖（盐湖）**
> · 汇水太猛、湖面顶到溢出点 → **外流湖**，多余的水从溢出点流走，形成出湖河

所以 H4 在 `findLakes()` 里加了第二步：**逐格注水 + 湖面水量平衡**。
判据里唯一的参数是 `potentialEvaporation`：

```
potentialEvapAt(tile) = potentialEvaporation × clamp01(temperature) × (1 − clamp01(moisture))
```

单位与 `runoff` 一致（1 ≈ 陆地平均产流），所以 `inflow` 与 `evap` 可以直接比大小。

**入流也用上了 MFD 的分流比例**（H2 只算了"主下游那一份"）：
`lakeInflow[y] += accum[x] × w.prob[j]`，对**所有**流入湖里的边累加。

### 7.2 标定（`tools/lab-lake.mjs`，新建）

扫 `potentialEvaporation × minLakeArea × minLakeDepth` 三维（默认 7×4×2 = 56 组），
输出 `tools/out/lab-lake.json` + 控制台表格。

**（a）`potentialEvaporation` 按物理量级定，不是凑 M18。**

先给硬证据：把 `minLakeArea=3`、`minLakeDepth=0.002`（即当前值）固定，只扫 PE：

| `PE` | 0.5 | 1 | **2（当前）** | 3 | 4 | 6 | 8 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 湖泊数 | 19 | 19 | **19** | 19 | 19 | 19 | 19 |
| 内流盆地数（M18，目标 5–25） | 6 ✅ | 7 ✅ | **9** ✅ | 11 ✅ | 11 ✅ | 12 ✅ | 13 ✅ |
| 其中干底盆地 | 1 | 2 | **5** | 5 | 5 | 6 | 7 |
| 分档 浅/深/盐 | 3/10/8 | 3/9/7 | **3/7/9** | 3/5/11 | 3/5/11 | 2/5/12 | 1/5/13 |
| 最大 5 湖的档位 | 全深 | 全深 | **全深** | 全深 | 全深 | 全深 | 全深 |

→ **M18 ∈ [5,25] 对 `PE ∈ [0.5, 8]` 全部成立**：单看 M18 根本定不下 PE（它不敏感）。
顺带两条稳定的观察：① **湖泊数与 PE 无关**（湖 = 地形洼地，PE 只决定水位与内外流判定）；
② **最大的 5 个湖在所有 PE 下都是外流深湖**（40/19/15/12/11 格，全不带盐标）。

既然 M18 定不下来，真正的锚只能是**量级**：

| 量 | 值 |
| --- | --- |
| 最干最热一格的蒸发 | `2.0 × 0.9 × 0.95 ≈ 1.7` |
| 陆地平均产流 `unit` | `≈ 0.25` |
| 比值 | **≈ 7 倍** |
| 地球实测 | 沙漠潜在蒸发 2000–3000 mm/a ÷ 全球平均径流 ≈300 mm/a = **7–10 倍** |

→ 取 **`potentialEvaporation = 2.0`**。

**（b）`minLakeArea` 4 → 3，并且 M17 的"湖泊数 ≥ 30"要改写。**

| `minLakeArea` | 湖数 | 洼地 ≤2 格的"小水洼" |
| --- | --- | --- |
| 1 | **31** | 9 |
| 2 | 21 | 2 |
| **3** | **19** | **0** |
| 4 | 15 | 0 |

M17 原文是"湖泊数 ≥ 30，最大湖 ≥ 15 格"。**"≥30"只有把 1–2 格的水洼也算成湖才能达到**，
而设计书 §10.1 明确说那些小水洼是**河流的过水段**，不该画成湖 —— 两个要求直接冲突。
所以口径改成**两者都真正表达意图**的那两条：

| 指标 | 判据 | 实测 |
| --- | --- | --- |
| M17 | 湖泊数 ≥ **15**（且一个 ≤2 格水洼都没有） | **19** 个 · 小水洼 **0** 个 |
| M17b | 最大湖 ≥ 15 格 | **39** 格 |

> **56 组扫描的命中数**（`lab-lake.mjs` 实时统计）：按改写后的 `M17+M17b+M18` 判据有 **27 行**命中；
> 按旧口径"湖泊数 ≥ 30"是 **0 行** —— **旧口径在全部 56 组参数里无一可达**，这是必须改写的硬证据。

**（c）`lakeShallowDepth` 看 `depthMean` 的分布定。** 实测湖深中位数 ≈ **0.0059** → 取 **0.006**。

| 档 | 判据 | 颜色 |
| --- | --- | --- |

**河线在湖边断开**（M38）：判据只加在**渲染层** ——
`isLine(x) = isRiver[x] && lakeId[x] < 0`。数据层的 `isRiver` / `accum` / `down` 一个都不动：

### 7.6 H4.5 施工记录：清零出边、迭代收敛、M33 口径

**① 怎么清（`blockSinks`，不动 CSR 结构）**

```js
prob[j] = 0        // 只对内流盆地格那一段出边清零
```

- `accumulate` 不再往下游发水（`× 0`）；`mainDownstream` **自然返回 −1**
  （它的 `bestP` 初值就是 0，`prob > 0` 一次都不成立）—— 这两处一行都不用改。
- 只清**内流盆地格**的出边，湖外的入边原样保留 → 上游照样流进湖里。
- 外流湖的出边不动（多余的水从溢出点流走，这正是"外流"的定义）。

**② 为什么是迭代（`sinkRounds`），不是算一次**

截断只减少**下游**的 `accum`，所以内流湖自己的入流基本不变；
但"上游还有内流湖"的那些湖入流会变小 → 水位更低 → 更容易变成新的内流湖。
内流集合因此**单调扩张**（只会 false → true，不会反向）⇒ 必然收敛、不会振荡。
**实测 1 轮即稳**（上限 5 只是安全阀）。拓扑序 `order` 只依赖 `filled`，所以提到外面算一次复用 ——
这让每轮的成本从"一次完整水文"降到"一次 accum + 一次提取 + 一次湖泊判定"。

**③ ★ M33 的口径必须一起改（否则这条断言等于没测）**

旧实现把"到达**任意**终点"都算成入海 —— 数学上：流图是**无环森林**，每个节点沿 `down`
必走到某个根 ⇒ 这个数**恒等于 100%**，H4 时它确实一直是 100%。
按设计书 §8.1 的原意"**最终入海**的河格 / 全部河格"重写：

- 追到**海格** = 入海；追到 `down = −1` = 进了内流盆地（不入海）；
- "可达性 = 100%"仍单独作为 **M13**（每个河格都走到某个终点，河网不悬空）；
- 两条"构造定理"随之改口径：内流盆地格的 `down = −1` 是**正确的**，

**画面上能看到什么**（H4.5 之后）：

| 看什么 | 怎么看 |
| --- | --- |
| 河网（树枝状） | 直接看星球；`setVisibleBiomes(['__none__'])` 可只留河线 |
| **湖** | 深蓝 / 亮蓝的**面**（湖面是顶点色，不是独立几何体） |
| **内流盆地 / 盐湖** | 灰青色的**面**，只出现在干旱区（例：`docs/river-shots/lake-salt-close.png`） |
| **河不从盐湖里流出去**（★ H4.5） | 找一个灰青盆地看：水到湖为止，河道在湖岸收口。对照 `sink-off.png` → `sink-on.png` |
| 湖面开关 | `setVisibleOverlays(['river','ore'])` → 湖消失；`setVisibleOverlays(null)` → 回来 |
| 只关 H4.5（看幽灵河回来） | `CONFIG.hydro.endorheicAsSink = false` + `refresh()` → 盐湖边上重新流出一条河 |
| HUD 读数 | 悬停任意格：「水系」行会显示 `湖#N（湿/洼 格 · 盐湖 · 深 0.006）` |
| 图例 | 右侧「覆盖层」组多了「浅湖（面）/ 深湖（面）/ 内流湖·盐碱滩（面）」 |

**回退**：

| 想撤销 | 做法 |
| --- | --- |
| 整个 H4.5 | `git revert <H4.5 的 commit>`；或只关开关 `CONFIG.hydro.endorheicAsSink = false` + `refresh()` |
| 整个 H4 | `git revert <H4 的 commit>`（数据层 + 渲染层都在这一个提交里） |
| 只关湖面 | `overlayVisible.lake = false` + `repaintAll()`（河网与群系都不受影响） |

| 整个 H2 | `git revert <H2 的 commit>`（H2 是**纯新增**：新增数据层 + 新增脚本，没有改动任何既有算法） |
