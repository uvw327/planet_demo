## 0. 为什么以 v1 为基准

v1 的核心特征是 **每个图块 = 一个固定纯色的 Mesh**（`BIOME_COLOR[biome]`），一共 12 种颜色。

这个做法有两个后果，而且**是同一个原因**：

- ✅ **干净**：颜色少、对比明确、图例可读、没有插值带来的浑浊，观感上是一张"分类地图"。
- ❌ **错误无法藏身**：分类结论被 100% 无损地画在屏幕上。所以"干净的错"看起来比"糊的对"更刺眼。

M2.5/M3 那条路线（顶点色插值 + 纸纹颗粒 + 烘焙光照 + 贴花墨线）之所以看起来像"发霉的乒乓球"，本质原因是：**它用渲染预算去掩盖模型缺陷**。模型里的三条因果链缺失（水汽输运、水往低处流、山脉成带）没有解决，于是先把缺陷画糊，再往上叠纸纹，两层问题相乘。

**因此本轮的判断是：保留 v1 的渲染架构（分类纯色），重做 v1 的自然模型。**

### P0-1 湿度场被 `clamp01` 削成"绝对沙漠环 + 湿度悬崖"

- **状态**：✅ 已修复（阶段 A）
- **症状**：
  - 存在一条**环绕整颗星球的绝对沙漠带**，带内 **99.4% 的陆地格子湿度精确等于 0**，没有任何梯度：没有绿洲、没有沿海湿润带、没有过境河谷、没有干湿分异。
  - 沙漠带赤道一侧与雨林之间**没有过渡**（直接黄 → 深绿），全星球草原只剩 142 格（1.39%）。真实世界的 Sahel（沙漠 → 半干旱草原 → 稀树草原 → 雨林）是一条上千公里宽的渐变带。
  - 极地反而"偏湿"（\|lat\| 70–80% 桶平均湿度 0.980），导致高纬出现 79 个"温带森林"。
- **证据**：
  - §1.3 表：30–40% 桶平均湿度 **0.000**、标准差 **0.0041**、零湿度占比 **99.4%**。
  - §1.5：副热带陆地带 76.8% 的格子湿度精确为 0。
  - §1.3：湿度从 0.005 跳到 0.375 只用了 10% 纬度（≈5.7°）。
  - 截图 `v1-shots/v1-desert-rainforest.png`（黄绿直接相接，中间无过渡色）。
- **代码位置**：
  - `latitudinalMoisture()`（`archive/v1-biome-globe.html:509`）—— 减性扣减 `Math.max(wetEquator, wetMidLat) * 1.15 - drySubtropic * 0.85`；
  - `computeClimate()`（`:527`）第 `:550` 行 `tile.moisture = clamp01(...)`；
  - 阈值 `moistureDesert: 0.30`（`:159`）、`moistureGrassland: 0.48`（`:160`）。
- **数值根因**：\|lat\| = 0.40 处 `max(wetEquator, wetMidLat) * 1.15 = 0.253`，`drySubtropic * 0.85 = 0.850`，结果 **−0.597**，被 `clamp01` 压成 0。缺口 0.597 远大于噪声项 `moistureNoise = 0.30`，所以噪声完全被吞掉。
- **违反的自然规律**：降水是**乘性**过程（水汽输运 × 辐合抬升），不是"从基础湿度里减掉一块"。减性模型在饱和后必然产生"零区"，而真实大气里副热带是"少雨"不是"无雨"。
- **修复方向**：
  1. 干旱带改为**乘性脱湿**（`m *= (1 - k)` 形式）或"下沉干燥只作用于已抬升的水汽"，保证任何位置都保留一点残余湿度；
  2. 给湿度场引入**可叠加的源项**（这才是后续 P0-4"水汽输运"的入口）；
  3. 重新标定 `moistureDesert` / `moistureGrassland`，让草原真正落进 0.30–0.48 区间。
- **验收标准**：
  - 任一纬度桶的"湿度=0 占比" ≤ 5%；
  - 副热带陆地带（\|lat\| 0.25–0.55）湿度标准差 ≥ 0.12；
  - 相邻纬度桶的平均湿度跳变 ≤ 0.15（现在最大跳变 0.370）；
  - **草原 + 稀树草原 ≥ 12% 陆地**（现在 1.39%）；
  - 沙漠带内出现非零湿度斑块（取决于后续是否加经向差异）。
- **实测（修复后）**：见 §3.1 阶段 A 实测与 §8 变更记录。核心结论：**"湿度=0"的陆地格从 76.8% 降到 0.0%**，副热带陆地带湿度标准差 0.1004 → **0.1640**，草原 1.39% → **12.86%** 陆地，沙漠 10.12% → **9.50%** 陆地（落在 8–18% 目标区间内）。"相邻纬度桶跳变 ≤ 0.15"这一条**经实测判定为错的目标**，已按 §3.1 的说明改写为"湿度直方图最大 bin 占比 ≤ 30%"（现 23.6%，且 20 个 bin 里有 18 个落在 3–5.6% 的平滑区间）。

**改写了一条错的目标（M11）**：原"相邻纬度桶平均湿度最大跳变 ≤ 0.15"来自"把悬崖当成噪声"的直觉。实际上三圈环流本身就决定了纬向剖面是"赤道湿 → 副热带干 → 中纬湿 → 极地干"的 V 形，相邻 10% 纬度桶之间**本来就该有 0.2–0.35 的落差**（真实地球降水从赤道 2000 mm 掉到副热带 200 mm，也是同一量级）。所以"跳变小"不是"修好了"，反而是"把气候带抹平了"。阶段 A 后该跳变仍是 0.338（从 10–20% 桶到 20–30% 桶），这是**正确的**。真正该测的是"分布是否在某个值处堆积成悬崖"，故改为上面的直方图指标：v1 是全陆地约 53% 的格子精确堆在 0；现在是 20 个 bin 里 18 个落在 3–5.6% 的平滑区间，只有饱和端（0.95–1.0）有 23.6% 的正常堆积。

**做了什么（3 处改动，都在 `index.html`）**：

| 位置 | 改前 | 改后 | 为什么 |
| --- | --- | --- | --- |
| `latitudinalMoisture()` | `max(wetEquator, wetMidLat) * 1.15 - drySubtropic * 0.85`（**减性**） | `wet * (1 - drySubtropic * subtropicDrying)`（**乘性**） | 减性在副热带中心给出 −0.597，被 `clamp01` 削成 0，缺口远大于噪声幅度，噪声被完全吞掉 |
| `computeClimate()` 湿度项 | `clamp01(base + jitter * 0.30)`（**加性**） | `clamp01(base * exp(jitter * 0.90))`（**乘性**） | 加性扰动在干旱区会把 base 推成负数再被截成 0；乘性扰动只要 base > 0 就恒 > 0，且波动幅度随 base 自动缩放（湿处波动大、干处波动小） |
| `moistureDesert` / `moistureGrassland` | 0.30 / 0.48 | **0.25 / 0.65** | 旧阈值是按旧湿度场定的，落在悬崖上。新阈值按新湿度场的分位重新落位（p27 / p63），让沙漠 / 草原 / 森林各占约三分之一 |
| 新增 `CONFIG.subtropicDrying: 0.45` | — | 副热带下沉脱湿强度 | 把"干旱带有多深"变成一个可调的物理量，而不是硬编码的 0.85 扣减 |

**顺带加的调参出口**：`window.__PLANET__`（`index.html` 的 init 末尾）。气候与分类都是纯函数，所以改完 `CONFIG` 直接调 `__PLANET__.refresh()` 就能看到新结果，不必重建 10242 个 Mesh、也不必重载页面（每次重载约 1 分钟）。后续 B/C/D/E 阶段的调参都靠它。对正常浏览无任何影响。

**还没做、留给后续阶段的（不是阶段 A 的职责）**：
- 沙漠带内部**仍有经向的完全同质性**——因为目前湿度只有"纬度 + 噪声"两个来源，没有**海陆距离 / 内陆干旱**（P0-4，阶段 C）。现在沙漠与草原的咬合来自大尺度噪声，还不是真正的"内陆干旱 + 沿海湿润"。
- 赤道附近出现了 54 格"热带草原"（\|lat\| < 0.1，温度 > `tempTropical`）。真实地球赤道也有萨王纳（东非），但这里出现得更像噪声造成的，属于 P1-5（气候格子太粗）的范畴。
- 高山 / 雪峰仍占陆地 41%（P0-3，阶段 D）——它把"参与湿度分类的陆地"压到只剩 35.6%，这也是草原难以进一步扩张的结构性上限。

  - 河流**与地形无关**：可横切山坡、可"往高处流"，因为 `\|noise\| < width` 的零值线与海拔完全无关。
  - 大量**凭空出现、凭空消失**的孤立河点与断头河。
  - 高山段被 `riverMaxElevation` 一刀砍掉 → 断头河的另一个来源。
  - 沙漠里照常有河（判定顺序在温度带之前，即 `biome === river` 优先于沙漠）—— 不是"过境河"，只是"噪声恰好过零"。
- **证据**：
  - §1.4 表：**126 个闭环**、**147 个连通分量**、最大水系只有 **44 格**、孤立河点 **13.0%**、断头河 **31.9%**。
  - 河流平均海拔 0.4824 vs 低地平均海拔 0.5039 —— 只低 0.021，且 p50/p95 与低地几乎重合（0.4731/0.6063 vs 0.5106/0.6352）。

- **代码位置**：`isRiver()`（`:483`）—— 整体都是噪声零值线判据；调用点 `:925`。
- **数学根因**：任何"标量场 < 阈值"的判据在球面上都是一组**闭合等值线**，闭合性来自拓扑，与参数无关。所以这个问题**不可能靠调 `riverWidth` 解决**。
- **违反的自然规律**：水往低处流；河流是**分水岭之间的树状汇流系统**；除三角洲/辫状河外河道不相交（无环）；河流必须通往海洋或内陆湖。
- **修复方向**：
  1. 引入 `downslope`（每格指向 6 邻居中最低者，或用水系求解填平后的方向场）；
  2. 引入**汇水累积**（上游贡献面积），河 = 面积（或流量）超过阈值；
  3. 引入**填平 / 洼地处理**（priority-flood），顺势得到**湖泊**与**内流盆地**（顺带解决 P1-1）；
  4. 产流量与湿度/降水挂钩，这样沙漠里天然无河。
- **验收标准**：
  - 河网环数 ≤ 3（现在 126）；
  - 连通分量 ≤ 30（现在 147）；
  - 最大水系节点数 ≥ 200（现在 44）；
  - 孤立河点占比 ≤ 2%（现在 13.0%）；
  - 河流平均海拔 ≤ 低地平均海拔 − 0.04（现在只差 0.021）；
  - 河流格的汇水面积中位数 ≥ 20 格。
- **实测（修复后）**：待填

### P0-4 湿度只依赖纬度，完全没有经向差异

- **状态**：⬜ 未修复
- **症状**：
  - **同一纬度的大陆西岸与东岸湿度相同**。真实世界的铁律是"副热带大陆**西岸**沙漠（撒哈拉、阿塔卡马、纳米布、澳洲西岸）、**东岸**湿润（中国东南、美国东南、巴西东南）"，v1 做不到。

- **证据**：

  - §1.5：副热带陆地带 76.8% 的格子精确为 0 —— 零经向差异的直接证据。
  - 截图 `v1-shots/v1-desert-rainforest.png`（黄色沙漠带是一条完美的纬向环带，东西无差别）。
- **代码位置**：`computeClimate()`（`:527`）—— `tile.moisture = clamp01(latitudinalMoisture(absLat) + moistJitter * CONFIG.moistureNoise)`；`moistureNoise: 0.30`（`:150`）、`climateScale: 1.50`（`:148`）。
- **违反的自然规律**：水汽是**被风输运**的（平流），降水来自**水汽辐合抬升**（地形抬升、锋面、对流）；大陆西岸在信风带是离岸风（干），东岸是向岸风（湿）。
- **修复方向**：
  1. 建立**风场**（至少三圈环流的纬向分量 + 经向分量，投影到球面切平面）；
  2. 把湿度改成**沿风输运 + 沿路降水 + 局地蒸发补水**的迭代/扫描求解（这是 v3 已经验证过可行的部分，可复用）；
  3. 地形雨影 = 抬升冷却 → 超容量降水；
  4. 内陆衰减 = 离海距离 / 上风向经过的陆地长度。
- **验收标准**：
  - 副热带陆地带内，**东岸/西岸湿度差显著**（定义：按经度 12 等分或按"上风向是海/是陆"分类，两组均值差 ≥ 0.10）;
  - 出现在上风侧山脉背风面的**干区**（可检测：山脉背风侧 5 格内的平均湿度低于迎风侧 ≥ 0.08）；
  - 湿度的**经向标准差**在非副热带区也 ≥ 0.08（现在赤道带只有 0.036）；
  - 三圈环流的**带序**仍成立（§2 第 2 条不得破坏）。
- **实测（修复后）**：待填

- **修复方向**：
  1. **短期**：把同色图块合并成一个大 `BufferGeometry`（顶点色 + 索引），draw call 从 10242 降到 1–12（按群系分组合并）；
  2. **长期**：合并成单一 geometry + 逐顶点色，此时 level 6 才可行。
- **实测（架构部分，已修复）**：全部图块合并成 **1 个 Mesh + 1 份材质**，draw call **10243 → 2**（星球 1 + 星空 1）；放矿后 4。拾取改 `faceIndex → triToTile`，往返抽样 **92/92 = 100%**；高亮改区间顶点色上传（72~84 字节/次），像素级验证通过。详见 `docs/render-architecture.md`。
- **验收标准**：level 5 下 draw call ≤ 20；或 level 6 下帧率 ≥ 30 fps；悬停高亮仍可用。
  → draw call 2 ✅；悬停高亮仍可用 ✅；level 6 现在是**纯配置**（`CONFIG.level = 6`），但仍需真机帧率确认，故本项标 🟡 而非 ✅。
- **症状 B（网格感）**：合并**不会**自动消除网格感（合并只解决 draw call）。是否要消除网格感仍是 §6 决策 D4，未动。
  → **2026-10-16 更新**：D4 已**被架构选择实际锁定为 ②（保留）**。为了保住"每格一个纯色"
  才刻意不跨格共享顶点，而"能数出格子"正是这个选择的必然结果；唯一的变化是**勾缝没了**
  （P2-4），现在是干净的颜色边界。若要改成 ③（主动描边，把网格线做成设计元素），
  需要额外一层线框，属于新工作量，可单独立项。

### P2-4 相邻六边形之间存在细暗缝

- **状态**：🟡 合并后**不再观察到**（需你目视确认）；观感本身待 §6 决策 D4
- **症状**：相邻图块共享顶点坐标（v1 已保证无缝隙），但**像素级抗锯齿**仍在边界产生混合，背景透出 → 出现细暗线，观感像"瓷砖勾缝"。
- **证据**：截图 `v1-a0.png` 沙漠黄区的蜂巢轮廓。
- **代码位置**：`buildTileGeometry()` 扇心 `center.clone() × avgRadius`；逐图块独立几何 + `DoubleSide`。
- **说明**：这个 artifact 意外地"帮忙"了（给了网格线），但它不是设计，合并成单一 geometry 后会自动消失。**需要你确认是要保留这种"网格感"还是要消除**（见 §6 决策 D4）。
- **实测（重构后）**：合并几何体 + `FrontSide`（v1 是 `DoubleSide`）之后，`docs/render-shots/render-close-selected.png` 的近景里相邻格边界是干净的、看不到暗缝——边界像素现在混合的是相邻格的不透明颜色，而不是透出背景。`seamFree: true` 也确认了公共边坐标逐位一致（无几何缝隙）。
- **验收标准**：暗缝在近景截图中不再可见 ✅（本项可按"已修复"结项）。
- **注意（别混淆）**：**暗缝（本项）≠ 网格感（P2-3 症状 B / D4）**。暗缝是"渲染 artifact"，已消失；
  而"能一格一格数出来"是"每格一个纯色"的**必然结果**，它没消失，也不该消失——
  这正是 §6-D4 被实际锁定为选项 ② 的原因。两者要分开验收。

## 8. 变更记录

### 阶段 A —— 修湿度悬崖（P0-1）｜2026-10-16

**目标**：消除"绝对沙漠环"，让沙漠带内出现梯度，给草原腾出空间。

**做了什么**（4 处改动，全部在 `index.html`）：

| # | 位置 | 改前 → 改后 | 理由 |
| --- | --- | --- | --- |
| 1 | `CONFIG` | 新增 `subtropicDrying: 0.45` | 把"干旱带有多深"变成可调物理量；旧代码里是硬编码的 `* 0.85` 扣减 |
| 2 | `CONFIG` | `moistureNoise: 0.30 → 0.90`，语义从"加性幅度"改为"乘性指数系数" | 配合第 3 项 |
| 3 | `latitudinalMoisture()` | `wet * 1.15 - dry * 0.85` → `wet * (1 - dry * subtropicDrying)` | 减性 → 乘性，永不为负 |
| 4 | `computeClimate()` 湿度项 | `clamp01(base + jitter * 0.30)` → `clamp01(base * exp(jitter * 0.90))` | 加性 → 乘性，消除 `clamp01` 造成的零区堆积 |
| 5 | `CONFIG` | `moistureDesert: 0.30 → 0.25`、`moistureGrassland: 0.48 → 0.65` | 按新湿度场的分位重新落位（p27 / p63） |
| 6 | init 末尾 | 新增 `window.__PLANET__` 调参出口 | 后续所有阶段的调参基础设施 |

**结果**：见 §3 P0-1 的"阶段 A 实测"表。一句话：**"湿度=0"的陆地格 76.8% → 0.0%，草原 1.39% → 12.86% 陆地，沙漠 9.50%（落在目标区间内），三条回归红线全部保持。**

**改掉了一条错的目标**：原 M11"相邻纬度桶平均湿度最大跳变 ≤ 0.15"被实测判定为错——三圈环流的纬向剖面本来就该是 V 形，跳变大才是对的。已改写为"全陆地湿度直方图最大 bin 占比 ≤ 30%"。

**回退方式**：`archive/v1-biome-globe.html` 是阶段 A 之前的基线快照，逐字节未动。要回到起点只需 `Copy-Item archive/v1-biome-globe.html index.html -Force`。阶段 A 本身的改动集中在 4 个位置（上表 #1–#5），全部可以用 `git revert <阶段 A 提交>` 干净回滚。

**目标**：手机端卡顿的根因是"每帧 draw call 数 = 图块数"，不是面数。把 10242 个 Mesh 合并成 1 个。

**这份改动只动渲染层与交互层：群系分布、气候、河流一行未动**，阶段 A 的全部结论依然成立。
