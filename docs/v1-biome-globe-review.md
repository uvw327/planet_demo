## 0. 为什么以 v1 为基准

v1 的核心特征是 **每个图块 = 一个固定纯色的 Mesh**（`BIOME_COLOR[biome]`），一共 12 种颜色。

这个做法有两个后果，而且**是同一个原因**：

- ✅ **干净**：颜色少、对比明确、图例可读、没有插值带来的浑浊，观感上是一张"分类地图"。
- ❌ **错误无法藏身**：分类结论被 100% 无损地画在屏幕上。所以"干净的错"看起来比"糊的对"更刺眼。

M2.5/M3 那条路线（顶点色插值 + 纸纹颗粒 + 烘焙光照 + 贴花墨线）之所以看起来像"发霉的乒乓球"，本质原因是：**它用渲染预算去掩盖模型缺陷**。模型里的三条因果链缺失（水汽输运、水往低处流、山脉成带）没有解决，于是先把缺陷画糊，再往上叠纸纹，两层问题相乘。

**因此本轮的判断是：保留 v1 的渲染架构（分类纯色），重做 v1 的自然模型。**

7. **无硬性数据错误**：无 NaN，center 均为单位向量，共享顶点为同一引用（无缝隙），五边形恰好 12 个。

### P0-1 湿度场被 `clamp01` 削成"绝对沙漠环 + 湿度悬崖"

- **状态**：⬜ 未修复
- **症状**：
  - 存在一条**环绕整颗星球的绝对沙漠带**，带内 **99.4% 的陆地格子湿度精确等于 0**，没有任何梯度：没有绿洲、没有沿海湿润带、没有过境河谷、没有干湿分异。
  - 沙漠带赤道一侧与雨林之间**没有过渡**（直接黄 → 深绿），全星球草原只剩 142 格（1.39%）。真实世界的 Sahel（沙漠 → 半干旱草原 → 稀树草原 → 雨林）是一条上千公里宽的渐变带。
  - 极地反而"偏湿"（\|lat\| 70–80% 桶平均湿度 0.980），导致高纬出现 79 个"温带森林"。
- **证据**：
  - §1.3 表：30–40% 桶平均湿度 **0.000**、标准差 **0.0041**、零湿度占比 **99.4%**。
  - §1.5：副热带陆地带 76.8% 的格子湿度精确为 0。
  - §1.3：湿度从 0.005 跳到 0.375 只用了 10% 纬度（≈5.7°）。
  - 截图 `v1-shots/v1-desert-rainforest.png`（黄绿直接相接，中间无过渡色）。
- **代码位置**：
  - `latitudinalMoisture()`（`archive/v1-biome-globe.html:509`）—— 减性扣减 `Math.max(wetEquator, wetMidLat) * 1.15 - drySubtropic * 0.85`；
  - `computeClimate()`（`:527`）第 `:550` 行 `tile.moisture = clamp01(...)`；
  - 阈值 `moistureDesert: 0.30`（`:159`）、`moistureGrassland: 0.48`（`:160`）。
- **数值根因**：\|lat\| = 0.40 处 `max(wetEquator, wetMidLat) * 1.15 = 0.253`，`drySubtropic * 0.85 = 0.850`，结果 **−0.597**，被 `clamp01` 压成 0。缺口 0.597 远大于噪声项 `moistureNoise = 0.30`，所以噪声完全被吞掉。
- **违反的自然规律**：降水是**乘性**过程（水汽输运 × 辐合抬升），不是"从基础湿度里减掉一块"。减性模型在饱和后必然产生"零区"，而真实大气里副热带是"少雨"不是"无雨"。
- **修复方向**：
  1. 干旱带改为**乘性脱湿**（`m *= (1 - k)` 形式）或"下沉干燥只作用于已抬升的水汽"，保证任何位置都保留一点残余湿度；
  2. 给湿度场引入**可叠加的源项**（这才是后续 P0-4"水汽输运"的入口）；
  3. 重新标定 `moistureDesert` / `moistureGrassland`，让草原真正落进 0.30–0.48 区间。
- **验收标准**：
  - 任一纬度桶的"湿度=0 占比" ≤ 5%；
  - 副热带陆地带（\|lat\| 0.25–0.55）湿度标准差 ≥ 0.12；
  - 相邻纬度桶的平均湿度跳变 ≤ 0.15（现在最大跳变 0.370）；
  - **草原 + 稀树草原 ≥ 12% 陆地**（现在 1.39%）；
  - 沙漠带内出现非零湿度斑块（取决于后续是否加经向差异）。
- **实测（修复后）**：待填

### P0-2 河流是"噪声等值线网络"，没有重力、没有汇水、没有湖泊

- **状态**：⬜ 未修复
- **症状**：
  - 河网是**蛛网/迷宫 + 散点**，不是树状水系。`v1-river-only.png` 一眼可见：满屏蓝色斑点与短棒。
  - 河流**与地形无关**：可横切山坡、可"往高处流"，因为 `\|noise\| < width` 的零值线与海拔完全无关。
  - 大量**凭空出现、凭空消失**的孤立河点与断头河。
  - 高山段被 `riverMaxElevation` 一刀砍掉 → 断头河的另一个来源。
  - 沙漠里照常有河（判定顺序在温度带之前，即 `biome === river` 优先于沙漠）—— 不是"过境河"，只是"噪声恰好过零"。
- **证据**：
  - §1.4 表：**126 个闭环**、**147 个连通分量**、最大水系只有 **44 格**、孤立河点 **13.0%**、断头河 **31.9%**。
  - 河流平均海拔 0.4824 vs 低地平均海拔 0.5039 —— 只低 0.021，且 p50/p95 与低地几乎重合（0.4731/0.6063 vs 0.5106/0.6352）。
  - 截图 `v1-shots/v1-river-only.png`。
- **代码位置**：`isRiver()`（`:483`）—— 整体都是噪声零值线判据；调用点 `:925`。
- **数学根因**：任何"标量场 < 阈值"的判据在球面上都是一组**闭合等值线**，闭合性来自拓扑，与参数无关。所以这个问题**不可能靠调 `riverWidth` 解决**。
- **违反的自然规律**：水往低处流；河流是**分水岭之间的树状汇流系统**；除三角洲/辫状河外河道不相交（无环）；河流必须通往海洋或内陆湖。
- **修复方向**：
  1. 引入 `downslope`（每格指向 6 邻居中最低者，或用水系求解填平后的方向场）；
  2. 引入**汇水累积**（上游贡献面积），河 = 面积（或流量）超过阈值；
  3. 引入**填平 / 洼地处理**（priority-flood），顺势得到**湖泊**与**内流盆地**（顺带解决 P1-1）；
  4. 产流量与湿度/降水挂钩，这样沙漠里天然无河。
- **验收标准**：
  - 河网环数 ≤ 3（现在 126）；
  - 连通分量 ≤ 30（现在 147）；
  - 最大水系节点数 ≥ 200（现在 44）；
  - 孤立河点占比 ≤ 2%（现在 13.0%）；
  - 河流平均海拔 ≤ 低地平均海拔 − 0.04（现在只差 0.021）；
  - 河流格的汇水面积中位数 ≥ 20 格。
- **实测（修复后）**：待填

### P0-3 "山脉 / 雪峰"是全局海拔阈值切出的 FBM 团块，不是山脉

- **状态**：⬜ 未修复
- **症状**：
  - 山脉 + 雪峰合计 **26.00% 陆地**，是球面上最大的两块"灰白斑"，观感像"岩石星球 / 发霉的雪原"。
  - 它们是**圆滚滚的团块**（FBM 高值区），不是**带状山脊**（没有走向、没有山脉链、没有水系分水岭）。
  - 与纬度完全无关 → 赤道的灰块和极地的灰块长得一样。
  - 雪峰与冰原/海冰在视觉上不可区分（都是白）。
- **证据**：
  - §1.2 表：雪峰 12.62% + 山脉 13.38%；雪峰平均海拔 0.911（`SNOW_LEVEL = 0.80`）。
  - 截图 `v1-shots/v1-a0.png`（南半球与极区大片灰白团块）、`v1-shots/v1-south.png`。
- **代码位置**：`SNOW_LEVEL = 0.80`（`:245`）、`MOUNTAIN_LEVEL = 0.65`（`:246`），判定在 `classifyBiome()`（`:569`，`:579`–`:580`）；海拔来源 `computeElevations()`（`:456`，混合 `continentScale 0.80` 低频与 `detailScale 3.00` 细节）。
- **违反的自然规律**：山脉是**构造运动的产物**，呈**线状/带状**（造山带），而不是各向同性的斑块；永久雪线以上（不含冰盖）仅占陆地的百分之几。
- **修复方向**：
  1. 把"山脉"从"海拔阈值"改成**独立的山脉场**（峰点 + 距离场，或脊线噪声），让它成**带/链**；
  2. 雪线判据交给**温度**（`雪线 = 温度阈值`），而不是全局海拔阈值；
  3. 给山脉不同的**视觉编码**，与冰原/海冰区分开。
- **验收标准**：
  - 山脉 + 雪峰占陆地 ≤ 12%（现在 26.00%）；
  - 山脉场的**连通形状**呈带状（可统计：山脉格的最小包围盒长宽比 ≥ 2.5，或骨架长度 / 面积比显著上升）；
  - 雪峰全部满足"温度低于雪线阈值"，且赤道雪峰仍存在（§2 第 3 条不得破坏）。
- **实测（修复后）**：待填

### P0-4 湿度只依赖纬度，完全没有经向差异

- **状态**：⬜ 未修复
- **症状**：
  - **同一纬度的大陆西岸与东岸湿度相同**。真实世界的铁律是"副热带大陆**西岸**沙漠（撒哈拉、阿塔卡马、纳米布、澳洲西岸）、**东岸**湿润（中国东南、美国东南、巴西东南）"，v1 做不到。
  - **没有地形雨影**：山脉不阻挡水汽（`elevation` 只影响温度，不影响湿度）。
  - **没有内陆干旱衰减**：超级大陆腹地与海岸一样湿（除副热带那条带）。
  - **没有洋流、没有海陆热力差**。
  - 等温线/等湿线是**完美同心圆**（`moistureNoise 0.30` 只是环形抖动，不是输运）。
- **证据**：
  - §1.3 表：湿度剖面是纯粹的单变量曲线；赤道带标准差仅 0.0359（几乎恒定）。
  - §1.5：副热带陆地带 76.8% 的格子精确为 0 —— 零经向差异的直接证据。
  - 截图 `v1-shots/v1-desert-rainforest.png`（黄色沙漠带是一条完美的纬向环带，东西无差别）。
- **代码位置**：`computeClimate()`（`:527`）—— `tile.moisture = clamp01(latitudinalMoisture(absLat) + moistJitter * CONFIG.moistureNoise)`；`moistureNoise: 0.30`（`:150`）、`climateScale: 1.50`（`:148`）。
- **违反的自然规律**：水汽是**被风输运**的（平流），降水来自**水汽辐合抬升**（地形抬升、锋面、对流）；大陆西岸在信风带是离岸风（干），东岸是向岸风（湿）。
- **修复方向**：
  1. 建立**风场**（至少三圈环流的纬向分量 + 经向分量，投影到球面切平面）；
  2. 把湿度改成**沿风输运 + 沿路降水 + 局地蒸发补水**的迭代/扫描求解（这是 v3 已经验证过可行的部分，可复用）；
  3. 地形雨影 = 抬升冷却 → 超容量降水；
  4. 内陆衰减 = 离海距离 / 上风向经过的陆地长度。
- **验收标准**：
  - 副热带陆地带内，**东岸/西岸湿度差显著**（定义：按经度 12 等分或按"上风向是海/是陆"分类，两组均值差 ≥ 0.10）;
  - 出现在上风侧山脉背风面的**干区**（可检测：山脉背风侧 5 格内的平均湿度低于迎风侧 ≥ 0.08）；
  - 湿度的**经向标准差**在非副热带区也 ≥ 0.08（现在赤道带只有 0.036）；
  - 三圈环流的**带序**仍成立（§2 第 2 条不得破坏）。
- **实测（修复后）**：待填

### P1-1 缺少湖泊 / 内流盆地 / 盐湖 / 湿地

- **状态**：⬜ 未修复
- **症状**：星球上没有湖。海平面以下一律是"海洋"，数据里的第 2 大水体（387 格）其实是一个**内陆海**，被画成海洋色。没有内流盆地、没有盐湖、没有河口三角洲、没有湿地/沼泽。

- **验收标准**：
  - 湖泊数 ≥ 30，最大湖 ≥ 15 格；
  - 内流盆地 5–25 个；
  - 湖泊有独立于海洋的颜色，盐湖/内流湖更深色；
  - 湖泊只出现在陆地洼地（湖面高程 ≥ 海平面）。
- **实测（修复后）**：待填

### P1-2 缺少海岸线 / 大陆架 / 浅海带

- **状态**：⬜ 未修复

- **违反的自然规律**：海洋有水深分带（大陆架 → 陆坡 → 深海），浅海是生物生产力最高的区域，也是玩家/观察者建立"岸线感"的主要线索。

- **验收标准**：海洋至少有 3 档深度色；环大陆出现连续浅水带；海岸线在视觉上一眼可辨。

### P1-3 海冰用纬度直线判定，不是温度等值线

- **状态**：⬜ 未修复
- **症状**：冰缘是**完美的圆**（\|lat\| = 0.93 ≈ 68.4°），与温度场脱节。海冰格子的平均温度 0.218 —— 恰好接近 `tempIce = 0.22`，纯属巧合。
- **证据**：§1.2 表海冰平均温度 0.218；§1.3 表 70–80% 桶（44°–53°）温度已低于 0.53 但仍无海冰。
- **代码位置**：`seaIceLatitude: 0.93`（`:142`），判定 `classifyBiome()` 第 `:575` 行。
- **违反的自然规律**：海冰边界由**海水温度**（以及盐度、洋流）决定，呈不规则的等温线形状。
- **修复方向**：海冰判据改为温度阈值 + 噪声扰动（或直接复用海洋温度场）。
- **验收标准**：冰缘随温度场波动（海冰边界的纬度分布标准差 ≥ 0.02）；海冰格子温度全部低于阈值；不出现赤道海冰。
- **实测（修复后）**：待填

### P1-4 温度场是"完美同心圆"

- **状态**：⬜ 未修复
- **症状**：`insolation = cos(lat)` + `±0.05` 噪声 → 等温线是同心圆。没有海陆比热差（内陆应更极端）、没有洋流（同纬西岸应更暖或更冷）、没有季节。
- **证据**：§1.3 表各桶温度与 `cos(lat)` 高度一致；`tempNoise: 0.05`（`:149`）。
- **代码位置**：`computeClimate()`（`:527`），`:541` 行的 `insolation - landRelief * CONFIG.lapseRate + tempJitter * CONFIG.tempNoise`。
- **违反的自然规律**：海洋热惯性大（同纬度海面温差小于陆地）；洋流（北大西洋暖流）能让同纬度西岸暖 10℃；海拔直减率是真实存在的（这一条 v1 做对了）。
- **修复方向**：温度加到"大陆度"项（距离海远近 → 振幅）与（可选）洋流项；噪声加大到能打碎同心圆但仍保留带序。
- **验收标准**：同纬度带上陆地温度的经向标准差 ≥ 0.05；海面温度的标准差 < 陆地；纬度-温度单调性仍成立（§2 第 1 条不得破坏）。
- **实测（修复后）**：待填

### P1-5 生物群系种类不足（12 种）

- **状态**：⬜ 未修复
- **症状**：仅有 海洋/海冰/河流/沙漠/草原/温带森林/热带雨林/针叶林/苔原/山脉/雪峰/冰原。缺 **稀树草原（Savanna）**、**地中海气候（硬叶林）**、**温带雨林**、**湿地/沼泽**、**红树林**、**灌丛/半干旱**、**盐湖**。

- **代码位置**：`BIOME`（`:197`）/ `BIOME_COLOR`（`:213`）/ `BIOME_LABEL`（`:229`）三张表 + `classifyBiome()`（`:569`）。
- **违反的自然规律**：`classifyBiome` 用的是"温度 3 档 × 湿度 2 档"的 2D 网格，真实生物群系是**温度 × 降水 × 季节性**的连续谱，尤其"稀树草原"是热带干湿季交替的产物（需要季节性概念）。

- **实测（修复后）**：待填

## 4. 修复路线图

原则：**每一步都能单独看见效果、单独回滚、单独验证**。不要并行施工两条以上 P0。

### 阶段 A —— 修湿度悬崖（最小改动，最大收益）

| 项 | 内容 |
| --- | --- |
| 目标 | 消灭"绝对沙漠环"与"湿度悬崖"，让**草原/稀树草原出现** |
| 涉及问题 | **P0-1**（+ P1-5 可顺带加"稀树草原"） |
| 改动范围 | `latitudinalMoisture()` + `computeClimate()` 的湿度部分 + `moistureDesert/moistureGrassland` 阈值 + 群系表 |
| 风险 | 低。不引入新数据结构，纯标量变换 |
| 验收 | §3 P0-1 的 5 条验收标准 |
| 预计产出 | 沙漠带变碎、出现绿洲边缘、草原从 1.4% 升到 12%+ |

### 阶段 B —— 给水加上重力（本路线最大的一次施工）

| 项 | 内容 |
| --- | --- |
| 目标 | 河网从"蛛网散点"变成"树状水系"，并**顺手带出湖泊与内流盆地** |
| 涉及问题 | **P0-2**、**P1-1**（+ P0-4 的"产流与降水挂钩"入口） |
| 改动范围 | 新增 `downslope` / 填平（priority-flood）/ 汇水累积 / 湖泊连通分量 / `isEndorheic`；`isRiver()` 整个替换；群系表加"湖泊/盐湖" |
| 风险 | **中高**。引入新的数据层（每个图块要加若干标量字段）；需注意遍历顺序（汇水必须"叶 → 根"） |
| 验收 | §3 P0-2 的 6 条 + P1-1 的 4 条 |
| 预计产出 | 树状长河、湖泊、内流盆地、盐湖 |

### 阶段 C —— 水汽输运（决定"耐看不出破绽"的上限）

| 项 | 内容 |
| --- | --- |
| 目标 | 引入**经向差异**：东西岸、雨影、内陆干旱 |
| 涉及问题 | **P0-4**（+ 复核 P0-1、P1-3、P1-4） |
| 改动范围 | 新增风场；湿度改为沿风输运 + 降水 + 蒸发的求解；温度加"大陆度"项 |
| 风险 | **中高**。求解器迭代是性能热点（v3 实测约占单步 21 ms）；必须保持确定性（同种子同结果） |
| 验收 | §3 P0-4 的 4 条 |
| 预计产出 | 大陆西岸沙漠 / 东岸湿润、山脉背风干区、内陆更干 |

### 阶段 D —— 山脉成带 + 真实雪线

| 项 | 内容 |
| --- | --- |
| 目标 | 山脉从"团块"变"带/链"，雪线由温度决定，把 26% 降到 ≤12% |
| 涉及问题 | **P0-3**（+ P1-5） |
| 改动范围 | 新增山脉场（峰点 + 距离场，或脊线噪声）；`SNOW_LEVEL` 判据改温度；`classifyBiome()` 的山地分支重写 |
| 风险 | 中。会影响温度（海拔→直减率），**必须重跑 P1-4 与新雪线的联合标定** |
| 验收 | §3 P0-3 的 3 条 + §2 第 3 条不得破坏 |
| 预计产出 | 带状山脉、山脊线、正确的雪线、山地占比回落 |

### 阶段 E —— 行星结构 + 视觉 + 架构

| 项 | 内容 |
| --- | --- |
| 目标 | 多大陆、海岸/浅海层次、色板平衡、（可选）地形起伏、draw call 优化 |
| 涉及问题 | **P2-1 ~ P2-6**、**P1-2** |
| 改动范围 | 低频包络改为多峰；海洋分档；色板重调；geometry 合并；可选 `enableHeightOffset` |
| 风险 | 中（架构改动，会动到交互拾取） |

| 预计产出 | 好看、耐看、跑得动 |

## 6. 待你拍板的决策

> 这些是**方向选择**，定了才好动手。每条我都给了倾向性建议，你可以直接说"按建议来"。

| # | 决策 | 选项 | 我的倾向 |
| --- | --- | --- | --- |
| D1 | **渲染架构** | ① 保持"每格一个纯色"（干净但 level 上限 5）② 合并为单一 geometry + 逐顶点色（可上 level 6，但会重新引入"插值浑浊"风险，需要控制配色）③ 分层：地形合并、边界单独描 | **②，但配色必须先规划好**。M2.5 的失败不是"插值"本身错，而是插值 + 纸纹 + 光照三层叠加；只保留"逐顶点色 + 明确色阶"是可以干净的 |
| D2 | **陆地占比目标** | ① 保持 62.9% ② 降到 30%–45% ③ 按地球 29% | **②**。陆地少一点 → 海洋显大 → 大陆度高 → 气候更有趣，也更容易做出"多大陆" |
| D3 | **是否要地形起伏** | ① 保持纯球面（v1 现状）② 打开 `enableHeightOffset` ③ 只给山脉做轻微隆起 | **③**，且**放在最后做**。起伏一旦打开，所有贴花层都必须跟随同一半径场（M2.5 的坑） |
| D4 | **六边形网格感** | ① 消除（合并 geometry 后自动消失）② 保留（当作"地图格子"语言）③ 主动描边（网格线成为设计元素） | **①或③，别停在中间**。现在是"意外产生的若有若无的勾缝"，最难看 |
| D5 | **是否引入季节** | ① 不做 ② 做一次"干季/湿季"相位，用来产生稀树草原 | 先 **①**；"稀树草原"先用"湿度中等 + 温度热带"近似顶上，季节留到阶段 C 之后再说 |
| D6 | **修复顺序** | ① 按 §4 的 A→B→C→D→E ② 先做 D（山脉）③ 先做 E（视觉/架构） | **①**。A 是性价比之王；E 放最后是因为它会打乱前面所有目视验证 |
